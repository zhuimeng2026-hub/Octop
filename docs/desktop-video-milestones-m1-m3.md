# Octop AI 视频制作：M1–M3 交付路线

状态：实施中。目标平台优先 Windows amd64，随后 macOS；视频渲染使用本机 Remotion Studio。

## 用户完整旅程
选择产品/上传素材 → 输入营销要求 → LLM 生成结构化镜头计划 → 业务人员编辑与确认 → 下载携带素材及固定依赖的制作包 → 本机 Studio 预览和 MP4 渲染。桌面客户端使用 Wails，Remotion 制作包无需额外部署 Octop 本地后端。

## M1 可安装桌面客户端（本阶段）
范围：基于已有 Wails 和产品素材库实现可供客户安装试用的客户端；本阶段不承诺 AI 自动生成视频。
- Windows amd64 安装包优先，其后 macOS；使用已有 portable Python 运行时和 NSIS。
- 安装后启动、正常进入 Dashboard，登录后可打开 `/product-library`，创建产品与上传素材。
- 再次启动仅激活已有 GUI，不重复创建 Python 服务；窗口关闭可恢复托盘。
- 现有配置/素材数据升级不应丢失；异常启动提示应可诊断。
- M1 轻量 CI：Go 编译及定向单实例/WebView 测试，Dashboard 构建，Python 素材库 API/迁移定向测试，以及 Remotion 启动器的类型检查与测试；真实 NSIS 打包复用已有 `octop-desktop.yml`。
- 试用验收：Windows 安装包成功生成，可安装、启动、登录、访问产品素材库；两个连续启动动作只保留一个桌面实例。真实 GUI/登录检查需要交互式 Windows 环境，CI 不替代实机体验。
- 不做：大型 LLM 视频编辑器、全量重构、全量 E2E 测试。

## M2 视频制作 Beta（M1 验收后）
1. 固定脚本契约：复用 `remotion/src/types.ts` 与现有 `script.json`，增加服务端字段校验及素材 ID 映射；先以确定性样例生成 ZIP 并渲染。
2. LLM 视频策划：输入产品快照、已确认卖点、素材索引与营销要求；使用低成本文本模型产生 JSON，服务端校验、重试/修复，避免每次都调用多模态识图。
3. 镜头工作台：卡片式查看与修改镜头时长、字幕、素材、顺序，支持逐镜头重新生成；保留草稿和已确认版本。
4. 制作包衔接：把已确认脚本交给已有 `package_export.py`，ZIP 中只带引用素材，保留 manifest/SHA256、锁定依赖及 Windows/macOS 启动器；本机 Studio 预览与导出 MP4。
5. M2 验收：业务人员能够从一个真实产品开始，完成修改脚本和实际 MP4 导出；不要求多轨视频编辑器。

## M3 客户试点版本（M2 验收后）
- 端到端冒烟：固定产品素材 → Mock LLM → 校验脚本 → 打包 ZIP → Studio 渲染短 MP4 → 校验时长与内容结构。
- 单独以低预算调用真实 LLM 联调一次，CI 不用付费模型。
- Windows/macOS 安装与卸载、二次启动、托盘恢复、网络不可用、失败重试及错误信息抽样验证。
- 收集实际客户反馈，修复阻断问题后再标注客户试点稳定版。

## 分支、成本与发布策略
- 每一阶段使用独立 PR，不直接在 `main` 开发；M1 先 `feat/m1-desktop-beta-readiness`。
- 日常 PR 只运行轻量质量门禁；耗时的六平台绿色运行时/安装包构建沿用现有独立 workflow；发布版必须验证相应 Windows 安装包。
- 配套 CI 如失败，先修复阻断编译/测试的直接问题；不为 M1 运行全仓库测试。
- 不把 GitHub Actions 绿色等同于真实 Windows 安装/登录已通过，完成程度据实记录。

## 顺序
M1 轻量 CI → Windows 安装包与人工启动检查 → M1 客户技术试用 → M2 脚本契约 → LLM 策划 → 镜头确认 → Studio ZIP 闭环 → M2 视频试用 → M3 冒烟及客户试点。
