## 决策：向导那层代码先做成脚本，暂不定归属

**结论**：MVP 阶段先把向导实现为脚本跑通，**不决定它落在本仓库内还是独立仓库**。

**理由**：

- MVP 的验收（AC-3 / AC-4）只验输出——`ffprobe` 实测 1080×1920 带字幕——**不验架构**。
- 归属决策依赖两件现在还不存在的事实：脚本跑通后的实际形态，以及「客户传图」这个交互最终长什么样。
- 现在定归属，等于为一个还没跑通的形态选位置，返工成本高于收益。

**什么时候再定**：脚本跑通、且 AC-5 / AC-6（真实商家走一遍）有结论之后。

## MVP 做什么

| 项 | 内容 |
|---|---|
| 交付物 | 一条 **1080×1920 带字幕**视频，能直接发 |
| 输入 | 商家传 3~5 张手机拍的商品图 + 回答两个问题（什么品类、想说什么） |
| 样板品类 | **沉香、玉石** |
| 渲染器 | 已定：本仓库 `remotion/`（**不再选型**） |
| 三句约束 | 骨架写死 · LLM 只写字幕与旁白 · 失败不重试 |

## 明确不做

多平台 · 抠像 / 背景分离 · 质量分档 · 向导 UI · 导入检查（只挡「打不开 / 太小」）·
brief 固定选项 · 校验降级 · 两条分镜差异化
