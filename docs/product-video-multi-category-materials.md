# 一条视频里混用多个产品分类的画面

> 状态：**活文档**（最近核实 2026-11-24）
> 文档结构：**第一部分**面向使用者（怎么用）；**第二部分**为工程侧需求与验收（依据与口径）。
> 冲突口径：第二部分是工程侧权威依据；与第一部分表述不一致时，以第二部分为准。
> 单一权威：跨产品分类选材这一主题**只在本文件维护**，其它文档请链接过来，不要另写一份 PRD。

## 第一部分 · 使用说明（面向创作者）

> 面向使用者：用 Octop 制作商品短视频的运营、买手和内容创作者。
> 适用位置：产品视频制作向导 → 第一步「选择产品」。

### 这是什么

以前，一条商品视频只能从一个产品下面挑画面。想把另一个分类里的镜头也放进同一条视频，
就得先做一条、再回来改，做不成一次成片。

现在，你可以在第一步里勾选**多个产品分类**，把它们的画面合并到同一批画面里，
一次生成方案、一次出片。成片里的标题、卖点和产品信息，仍然以你指定的那个**主推产品**为准。

打个比方：主推产品是这次要推销的主角，其他分类是"顺带出镜"的补充画面。

### 开始之前先确认

| 你要做的事 | 在哪里做 |
| --- | --- |
| 建产品、写产品名、型号、分类、卖点 | 产品素材库 → 添加产品 |
| 上传图片和视频 | 产品素材库 → 对应产品 → 上传 |
| 把素材标记为「画面素材」 | 上传时或素材列表里设置用途 |
| 停用不想再用的素材 | 素材列表里关掉它 |

三条硬性前提，缺一个素材就不会出现在画面列表里：

1. 素材已经归到某个产品下面；
2. 素材的用途是**画面素材**（"理解参考"和"风格参考"只给 AI 看，不会上片）；
3. 素材没有被停用。

### 制作步骤

#### 第一步：选择产品与画面素材

这一屏上有三个东西，从上往下看：

**「产品」下拉框 —— 主推产品。**
它决定这条视频的主角：标题、卖点、给 AI 的产品事实都取自它。
换了主推产品，等于重开一条方案：原来的画面选择、还没上传完的素材、已经写好的制作要求都会清空，
新主推产品的画面重新勾上。

**「素材分类」多选框 —— 画面从哪来。**
- 里面每一项写着「产品名 · 分类名」，主推产品默认已经在里面，而且**不能取消**。
- 选中一个分类，它的画面就会合并进下面的画面列表。
- 可以随时追加或取消其他分类。

**「本次可用素材」—— 合并后的画面。**
- 来自不同产品的画面会带上它属于哪个产品，方便你认出同名文件。
- 新追加的分类，画面默认全部选中。已有分类保留原来的勾选状态；点一下卡片可以取消勾选，再点一下恢复。
- 「补充素材」可以临时补拍：补进去的文件归到**当前主推产品**下面，不会混进别的分类，也不会打乱你已经选好的画面。

#### 第二步：制作要求

写清楚视频用途、目标平台、语言、画幅、每张画面停留几秒、要不要带上产品卖点。
默认的竖屏、单张 4 秒通常可以直接用。

#### 第三步：AI 视频方案

点「生成 AI 视频方案」，AI 按你勾选的画面排出分镜脚本：片头、逐个画面、片尾。

#### 第四步：确认调整

逐个镜头核对画面和文案，可以改单个镜头的时长、换画面、调顺序。改完记得保存并确认。

#### 第五步：下载制作

确认后的方案可以下载制作包，在本机渲染成 MP4；桌面端也可以直接在本机出片。

### 什么是「成片清单」

一旦你点了生成，这份方案里的画面就被**固定下来**了——用的是哪几张图、来自哪个产品、
每张的时长和用途，全部锁定。界面上会提示你「项目已建立快照」，说的就是这件事。之后：

- 你再改产品名、改卖点，不影响已经做好的方案；
- 你停用或者删掉产品里的素材，不影响已经做好的方案；
- 已经做好的方案**不能再加画面**。想加，回产品素材库另建一条方案。

这是有意为之：已经确认的方案就该保持原样，避免改到一半发现成片和当时想的不一样。

### 你的素材只有你能用

- 一条方案里的所有画面，都必须来自你自己的账号。
- 别人的素材哪怕你已经知道编号，也塞不进你的方案。
- 反过来，你的素材也不会跑进别人的方案里。

### 常见问题

**Q：加了一个分类，画面一个都没多？**
A：那个分类下面可能还没有"可用于画面"的图片或视频。资料类的素材、被停用的素材都不会进画面列表。
先回产品素材库确认这个产品下确实有标了「画面素材」的文件。

**Q：为什么主推产品移不掉？**
A：它是这条视频的主角，标题和卖点都要从它这里取。去掉它，方案就没有主角了。

**Q：我切换了主推产品，之前选的画面全没了？**
A：会清空，这是设计如此。切换主推产品就是重开一条方案，新主推产品的画面会重新勾上。

**Q：我补传的图片算在哪个分类里？**
A：算在当前主推产品下面。想让它出现在别的分类下，要在那个产品下单独上传。

**Q：能不能把两个账号的素材混在一条视频里？**
A：不能，也不应该。

**Q：同一份选择点了两次生成，会得到两条方案吗？**
A：会。两份内容一致，但互相独立，改一份不影响另一份。

### 已知限制

- **方案建立后不能再加画面。** 要加只能另建一条方案。
- **单条视频有时长上限。** 所有镜头加起来最多 180 秒；AI 排出的镜头数量也有上限。
  素材挑得太多时，超出部分不会出现在分镜里。

### 界面对照

| 界面上看到的 | 指的是 |
| --- | --- |
| 产品 | 你要推销的那件商品，可以有多个 |
| 分类 | 商品的品类标签，比如"夏季上新""清仓款" |
| 素材分类（多选） | 这次视频允许取用画面的产品分类，可以多选 |
| 画面素材 | 会真正出现在成片里的图片或视频 |
| 理解参考 / 风格参考 | 只给 AI 看、不上片的文件 |
| 本次可用素材 | 所有已选分类合并后的画面 |
| 项目已建立快照（界面提示） | 这条方案已经定稿，画面清单固定 |
| 成片清单 | 方案里固定下来的那份画面名单 |
| 补充素材 | 制作过程中临时补传的画面，归到主推产品 |

## 第二部分 · 工程侧需求与验收（权威依据）

> 目标读者：前端 / 后端 / 测试。
> 本部分是该功能的**工程侧需求与验收依据**，与第一部分结论一致；如有出入以本部分为准。
> 其它文档（产品素材库整体规划、目录导入架构）请链接到本文件，不要另写一份需求。

### A1 背景

产品视频制作向导原先只能选择单个产品下的图片和视频素材。当用户需要把不同产品分类、不同素材组中的画面组合到同一条视频时，只能反复返回产品素材库，无法在一次制作流程中完成选择。

### A2 目标

允许用户在视频制作向导中跨产品分类选择图片和视频，并将所选素材作为同一个视频项目的不可变快照提交给后端。

### A3 用户与场景

- 用户拥有多个产品或素材分类。
- 用户希望以一个主产品作为视频标题、卖点和生成要求的基础。
- 用户需要从其他产品分类中补充画面素材。

### A4 产品方案

#### A4.1 主产品

- 保留现有「产品」选择器。
- 主产品负责视频名称、产品卖点和生成要求中的产品事实。
- 更换主产品时，清空当前项目草稿、上传队列和素材分类选择，并以新主产品作为默认分类。

#### A4.2 素材分类多选

- 在产品选择器旁新增「素材分类」多选器。
- 默认选中当前主产品。
- 用户可以追加其他产品分类；主产品始终保持选中，避免项目缺少主产品上下文。
- 选择分类后，向导合并加载这些分类下的有效 `scene` 图片和视频。
- 素材卡片在来自其他分类时显示来源产品名称，帮助用户区分同名文件。
- 已建立项目的素材快照保持锁定，分类选择器不可修改。

#### A4.3 素材选择

- 分类加载完成后，新增分类中的可用素材默认加入本次选择。
- 用户可以逐张取消或重新勾选素材。
- 从产品素材库带入的显式初始选择只在首次加载时生效，后续追加分类不会覆盖用户已经做出的选择。
- 上传补充素材仍归属于当前主产品；上传成功后不影响其他已选分类的素材。

### A5 后端要求

- 创建项目时仍使用一个 `product_id` 作为主产品 ID。
- `asset_ids` 可以包含同一用户不同产品下的素材 ID。
- 后端必须按素材 ID 和用户归属校验，禁止跨用户读取或快照素材。
- 项目快照中的每条素材记录保留 `product_id`，并继续保存文件路径、媒体类型、用途、优先级和内容哈希等信息。
- 项目创建后快照不可变；后续编辑或删除产品不应改变已创建项目的素材内容和主产品信息。
- 不新增独立 API；沿用现有项目创建接口，通过放宽素材归属校验支持跨产品素材。

### A6 国际化

新增中文和英文文案：

- 素材分类
- 选择素材分类（可多选）
- 可跨产品分类选择素材库中的图片和视频
- 所选素材分类没有可用于画面的图片或视频

### A7 验收标准

分六组。每条都可以落到一条可执行的检查（自动化用例或一次可复现的手工走查），不写「应该好用」这类无法判定的话。

#### A7.1 分类选择与素材勾选

1. 进入视频制作向导后，素材分类多选器默认包含主产品。
2. 选择第二个产品分类后，该分类下的有效图片和视频出现在素材列表中。
3. 主产品与第二个分类的素材可以同时勾选。
4. 点击下一步并生成视频方案时，创建项目请求包含两个分类的素材 ID。
5. 后端成功创建跨产品素材快照，并为每条快照素材保存来源产品 ID。
6. 切换主产品后，旧产品的素材和选择不会残留。
7. 已有项目重新打开时，仍只显示项目快照中的素材，不能修改分类或素材。
8. 不同用户的素材 ID 不能被加入当前用户的项目快照。
9. 主产品在多选器中不可移除：无论用户如何操作，主产品始终处于选中态。
10. 追加一个分类不会改写用户已有选择——用户手动取消勾选的素材，在追加分类、重新加载、加载失败后重试之后仍保持取消。
11. 追加分类时，新分类中的可用素材默认进入勾选态，且与用户此前的勾选结果合并而不是覆盖。
12. 从产品素材库带入素材时，带入的显式勾选仅在首次加载生效；用户后续手动调整的结果不被回退。
13. 上传补充素材归属于当前主产品；上传成功后其他已选分类的素材与勾选状态不受影响。
14. 素材卡片在来自非主产品分类时显示来源产品名称，用于区分同名文件。

#### A7.2 权限与数据隔离

15. 创建项目时只接受一个主产品 `product_id`，其余素材仅通过 `asset_ids` 表达。
16. 后端按 `owner_user_id` 校验每一条素材，任一条不属于当前用户则整单失败，不产生半成品项目。
17. 越权请求的响应不泄露素材是否存在——他人素材与不存在素材返回同一类错误，避免用错误码枚举他人素材 ID。
18. 素材归属校验按「用户 + 素材 ID」，不按「用户 + 主产品」，否则跨分类素材会被误判。
19. 用户 B 的素材 ID 无法通过向导、接口直连或篡改请求进入用户 A 的项目快照。
20. 接口不新增跨用户读取通道，素材列表与详情接口保持用户隔离。

#### A7.3 快照一致性与不可变性

21. 快照保存每条素材的 `product_id`、文件路径、媒体类型、用途、优先级与内容哈希，字段齐全且与来源一致。
22. `asset_ids` 顺序不影响快照内容；重复 ID 在快照中去重，只保留一份。
23. 项目创建后快照不可变：修改或删除源产品、改名、归档或删除素材，都不改变已建项目的素材内容与主产品信息。
24. 项目重新打开时，界面数据一律来自快照，不再回查源产品的当前状态。
25. 源素材在创建前已被归档（`active = 0`）时，创建请求**必须（MUST）整单失败**并明确提示被停用的素材；**不得（MUST NOT）**静默丢弃，**也不得（MUST NOT）**部分成功后再仅在响应中说明。实现契约见 A8.1。
26. 重复提交同一份 `asset_ids` 产生内容一致的两个项目，不因顺序或调用次数产生差异。

#### A7.4 交互与可访问性

27. 素材分类多选器与产品选择器有各自可区分的可访问名称，键盘可达、可操作。
28. 切换步骤后焦点移动到新步骤标题或该步骤的首个操作，不落在页面根节点。
29. 素材加载中、加载失败、加载为空三种状态有可区分的文案与各自的下一步操作。
30. 加载失败时提供重试入口，重试不改变用户已做的选择。
31. 勾选状态变化有可见反馈，已选数量随勾选实时更新。
32. 追加分类造成的重新加载期间，素材网格不闪烁、不清空已有内容。

#### A7.5 性能与规模

33. 多个分类的素材合并去重后展示，同一素材不会因跨分类重复而出现两次。
34. 素材量达到数百条时，勾选、切换分类与提交仍可交互，不出现明显卡顿。
35. 分类切换引发的重复加载有去重或取消机制，旧请求返回不得覆盖新状态。
36. 提交项目时只发送被勾选的素材 ID，不发送整个素材列表。

#### A7.6 自动化回归基线

37. 前端：跨分类加载与提交、越权路由选择不继承、切换产品后忽略过期响应三类用例在 `dashboard/src/pages/ProductVideoWizard/index.test.tsx` 中有对应用例。
38. 后端**必须**覆盖跨产品素材快照写入与跨用户素材拒绝（尤其混入他人素材时整单原子失败），并在 `tests/unit/db/test_product_library_repo.py` 中有准确的对应用例。
39. `npx tsc -b` 与 `uv run pytest tests/unit/db/test_product_library_repo.py -q` 通过；其余全量测试交给 CI。

**第 10 条的缺陷与修复。** 素材加载 effect（`dashboard/src/pages/ProductVideoWizard/index.tsx`）原先在每次重新加载后把「全部可用素材」并入选中集合：

```ts
return [
  ...new Set([
    ...currentIds.filter((assetId) => availableIds.has(assetId)),
    ...available.map((asset) => asset.id),
  ]),
];
```

追加分类、手动重试加载都会走这条路径，于是用户手动取消勾选的素材会被重新选中。用临时回归用例复现：主产品下取消勾选一张图，再追加第二个分类，该图重新变为选中态。

修复方式是区分「首次进入分类」与「已有选择」两种情形：用 ref 记录已经加载过的分类，
只有**新出现**分类的素材默认选中，已经加载过的分类保持用户当前勾选状态。
配套行为：

- 移除某个分类时，该分类的素材自动取消勾选并从画面列表消失；
- 重新添加被移除的分类时，它的素材按「新出现分类」处理，重新默认选中；
- 切换主产品是「重开一条方案」，需要把已加载分类的记录清空，让新主产品的画面重新默认选中
  （否则会出现「切到一个曾经当过附加分类的产品，画面却一个都没勾上」的不一致）。

### A8.1 第 25 条的实现契约（2026-11-24 决策，待实施）

**决策：整单失败并提示。** 决策理由一并记入本节，便于后续复核时重新评估：

- **快照语义必须自洽**：项目快照 = 用户勾选的素材集合。若允许跳过，快照与用户所见不一致，A7.3 的第 21、23 条将无法判定。
- **不引入「部分成功」响应模型**：现有 `POST /product-library/projects` 的响应是 `ProjectResponse`，没有承载「跳过项」的字段；新增字段会牵动响应模型、快照结构与前端展示三处。
- **触发面很窄**：向导只加载 `active` 素材，只有「选中后素材被停用」的竞态才会命中，用户据提示重选即可。
- **与 A7.2 第 17 条不冲突**：仅对**当前用户自己的**停用素材给出具体提示；他人素材与不存在的素材继续返回同一类 404，不泄露存在性。

**契约（实现时必须满足）**：
