# 产品素材库第一批 MVP：详细设计与实施约定

日期：2026-10-29。目标分支：`fix/backend-mvp-v01-integration`。
代码核对基线：`d16bd0243edab026cadab0fc2cfc583a0c7b7719`。

## 1. 目标与范围

让业务人员完成「建产品 → 批量导入 → 看图勾选 → 用所选素材制作视频」，素材只上传一次，后续项目复用。第一批不增加 AI 标签、自动卖点识别、智能镜头匹配、素材缺口分析或新模型服务。保留已有 AI 分镜、人工调整、下载制作包和桌面渲染能力。

核对源码后确认：当前分支已有 React 产品素材库、五步视频向导、FastAPI 上传接口、SQLite/PostgreSQL 元数据、按用户隔离的磁盘文件和不可变项目快照。无需新增数据库或重写整个前端。之前的 3–5/7–12 人日属于未核实源码的估算，不作为本次实施承诺。

## 2. 已有能力及实际缺口

| 能力 | 现有实现 | 本次改动 |
| --- | --- | --- |
| 产品建档 | 名称、型号、分类、卖点、参数、表达限制 | 保存后自动选中新产品，立即导入 |
| 素材持久化 | 元数据在现有 DB；文件在 product_library_dir；SHA256 去重 | 复用，不重复建库 |
| 批量上传 | 一个请求上传多文件，统一用途，默认 reference | 默认按扩展名归类；逐文件上传，展示进度，保留失败项重试 |
| 查看素材 | 搜索、媒体类型筛选、手动预览 | 图片卡片自动加载预览；视频点击加载，避免批量下载大视频 |
| 用途与选取 | scene/reference/style、启用、优先、复选框 | 显示可用于视频的已选数量；默认仅选启用的 scene 图片/视频 |
| 视频入口 | 只打开空白向导 | 当前产品和本次勾选带入第一步，保留用户主动取消的选择 |
| 后续生成 | 项目快照 → 现有分镜 → 制作包/桌面渲染 | 继续使用，不自动调用 LLM 或自动创建项目 |

## 3. 页面与交互

沿用已选的五步向导、现有 Ant Design、主题和中英文文案，不另建视觉系统。

产品列表继续提供搜索、名称、型号、分类。新建只要求产品名称；保存成功后自动进入该产品素材区。无产品时给出明确的新建入口；加载失败与空库应有不同提示及重试。

素材区使用可自适应换行的卡片，每张呈现预览、名称、类型/大小、用途、选中及启用状态。图片通过现有认证下载接口获取 blob，不把登录令牌写入 URL；视频按需加载。切换产品、账号或卸载时回收对象 URL，丢弃旧异步结果，避免串图。图片预览失败提供重试。筛选只改变可见集合，不丢失隐藏素材的选择。提供「选择可用素材」「清空选择」。

主操作为「用已选素材制作视频」，显示可用已选数量。仅启用且用途为 scene 的图片或视频可进入视频选择；资料文档不充当镜头，reference/style 不自动改为 scene。零可用素材或正在上传时禁用该操作并说明原因。原有项目快照、下载和高级操作保留。

## 4. 导入规则

默认「自动分类」：按服务端允许的扩展名识别图片/视频，标记 scene；允许的文档标记 reference。仍可人工选择统一用途。文件选择器提供支持格式提示，未知格式明确提示失败，不伪装成功。

每次串行上传一个文件，复用原上传接口，从而能准确说明「已处理 n/m，成功 s，失败 f」。成功项从待上传队列移除，失败项保留并可重试；同名不同文件按队列索引/标识处理，不因文件名相同一起移除。批次中禁用文件增删及冲突操作。去重行为沿用后端：同产品同内容返回已有记录，不自动覆盖其用途/启用状态。

批次结束重新读取素材；保留仍有效的原选择，只追加本批新上传且可用于视频的素材，不把用户之前取消的旧素材重新全部选中。即使部分失败也刷新已成功内容。网络错误明确反馈；切换产品/账号后的迟到结果不得修改当前页面。

视频向导现有上传入口也应遵守保留选择和失败可重试原则，但只接受可播放媒体；复用公共纯函数或小组件，避免重构整个向导。

## 5. 页面衔接与权限

素材库导航到 `/product-library/video-wizard?product=<id>`，通过 React Router state 传递 `{ productId, assetIds, ownerId }`。这是非敏感的临时选择，不存 token 或文件内容。向导根据当前登录用户重新读取产品和素材，交集校验产品归属、active、usage 和 media_type；不能信任路由 state。明确传入空数组时不得回退为全选。

刷新时允许回到该产品默认的可用素材选择；界面仍停在第一步等待确认，不自动生成。切换账号不沿用另一账号的路由选择；产品不属于当前账号时提示不可用。继续已有 `?project=` 项目优先于新产品参数，保持原快照和确认草稿行为。

数据仍由服务端根据登录身份隔离。这里的「本地保存」是 Octop 所部署机器的文件目录：本机部署保存在本机，云端部署保存在服务器，不宣称浏览器设备离线存储。下载制作包后才在客户本机 Remotion/桌面端渲染。

## 6. 接口、数据与兼容

继续使用 `/api/product-library` 下现有 products、assets、projects、storyboard、package 接口，不增加 migration、同步服务或新后端。产品/素材公共 ID 原样传递，所有下载和更新仍经现有认证请求封装。项目保存产品及素材快照；以后修改库内容不改变旧项目。手工更改用途或停用后同步调整可用选择，不保留不可用的勾选计数。

主要修改位置：`dashboard/src/pages/ProductLibrary/`、`dashboard/src/pages/ProductVideoWizard/`、必要的共享选择/导入辅助函数，以及 `dashboard/src/locales/{zh,en}.json`。只有发现阻断第一批闭环的具体后端问题时才做最小修复并补充文档。

## 7. 验收与基础检查

1. 新建产品后无需再次寻找该产品即可导入；重进页面能读取持久化素材。
2. 混合图片、视频、文档默认分类正确；部分失败不掩盖成功，重试不丢队列。
3. 取消一个旧素材后补传新素材，旧素材保持取消；同名不同文件可以单独移除。
4. 素材库所选产品和素材准确带到向导；未选、禁用、资料和其他产品素材不进入项目请求。
5. 切换产品/账号或快速返回时，旧响应和预览不得串入新上下文。
6. 既有项目继续编辑/导出流程保持可用；后端既有隔离、快照和打包测试作为回归依据。

按用户本轮沿用的 MVP 基础验证约定：执行相关组件测试、TypeScript 检查及前端构建，针对触及的后端运行定向测试，不跑全量套件。增设目标分支的定向 CI，推送后检查结果。真实 LLM、Windows 安装包及真实 MP4 全链路仍需部署环境验收，不能以模拟组件测试替代。

## 8. 实施安排

先保存本设计作为实现依据，由低成本模型完成代码与定向用例，再由主代理复核关键选择、异步状态、权限与回归结果。仅推送用户指定分支，不合并主干。最终在本文记录实际改动与检查结果。
