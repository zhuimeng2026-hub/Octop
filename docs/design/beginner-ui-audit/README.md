# Octop 新手界面复核与修改建议

日期：2026-11-24 · 状态：待批准 · 仓库：Octop，`feat/video-production-workbench`，本地工作树（HEAD `cfcb0d19`）

## 审查范围

面向第一次用 Octop 做商品视频、没有剪辑经验的内容创作者。任务是用本机商品图片生成首条短视频，能看懂哪些步骤可跳过、遇到故障怎么继续，以及在哪里拿到成片。重点是 Windows 客户端的精简模式，另看了 Web 的无登录方式状态。通用控制台和管理流程未纳入本轮。

保留当前三项精简导航、五步向导、快速分镜默认值与按需安装。首轮建议集中在现有界面的入口、文案、状态和返回路径。

## 建议与验收

优先级按首次做成视频的影响排序。建议首批批准 A–C，D–E 可单独批准。

| 项目 | 建议 | 修改原因 | 可复验的结果 |
| --- | --- | --- | --- |
| **A · P1 · 从导入开始** | 空向导只突出「导入图片」，用一句话说明选择含商品图片的文件夹。优先复用素材库入口和现有目录选择器。素材库空状态给出同名主操作。已有素材时在主操作旁写「已选 N 张」；数量上限移到筛选或达到上限时。 | 第一步应该告诉用户要准备什么、点哪里。素材为空时，归档术语和上限都不能帮助继续。 | 空库时主按钮通向已有导入流程。选择图片后主操作与数量同步更新。从素材库带一张图进来，向导只勾选那一张。依据图 02、03、05。 |
| **B · P1 · 区分导入与识别** | 将双重失败提示归为一条明确的结果，例如「已导入 2 张图片。AI 未能识别，仍可选图制作视频」。保留识别重试为次级操作。在素材状态附近说明文件已保存在本机，以及 AI 识别会由服务处理。 | 成功提示消失后，醒目的「失败 2 个」容易被当成导入失败。现有产品允许未归档素材直接生成快速分镜，但入口在告警和归档模块下方。 | 用两张图模拟识别失败，页面仍显示已导入数量和继续方法。勾选一张可直接进入同一向导，重试识别仍可单独触发。依据图 04、05。 |
| **C · P1 · 组件安装与失败恢复** | 到生成步骤再提供「安装视频组件」主按钮和简短原因。安装或查询中用状态和进度反馈，完成后用「返回并生成视频」。向导未完成时，从侧栏往返组件页也应恢复同一阶段、选图和分镜修改。失败页用「视频未生成」及「重新生成视频」，将技术码放入诊断详情。完成页用明确的「下载 MP4」主按钮，保持预览可用。 | 初次依赖缺失时，提示链接和禁用按钮本身没有指出做完如何回来。两条返回路径效果不同，造成返工。生成失败和成功需要不同的下一步。 | 缺组件时仍能生成分镜。修改一个镜头时长，从向导内或侧栏往返后都能看到现场和修改。模拟失败可直接重试并保留方案，连续点击只触发一次任务；成功后可播放，下载动作仅在有可用输出时出现。依据图 08–11 和步骤 5 的返回复测。 |
| **D · P2 · 简化默认生成与检查** | 将「快速分镜」呈现为推荐选项，解释会按图片生成基本镜头。默认展示视频标题和画幅，更多参数可展开；没有产品卖点时显示当前不可用的原因。检查页加总时长和镜头数，以「继续生成视频」标记下一步，保持下一步易找到。 | 初学者可以直接使用现有默认值，页面却要求先理解「分镜方式」和「包含产品卖点」。总时长与镜头数可帮助判断视频是否适合用途。 | 默认可直接生成分镜；展开后的既有选项仍能编辑。用本轮一张样图，检查页显示 3 个镜头、9 秒；改时长后汇总同步更新。在 1280 × 720 下可明确定位主操作。依据图 06、07。 |
| **E · P2 · 登录阻塞与无障碍** | 无登录方式时提升提示对比度，区分加载、网络失败和确无可用方式。只在条件适用时显示「重试」或现有帮助入口。给选择素材来源和每镜头时长控件关联可见标签；切换步骤后将焦点移到新步骤标题或首个操作，反馈状态需可被读出。 | 登录故障目前缺少后续动作。走查中素材来源下拉框和分镜时长控件在浏览器可访问性树中无明确名称，切换步骤后焦点落到页面根节点。 | 无登录方式、请求失败、加载中各有可区分的文字。用 Tab 和 Enter 可完成选图到生成流程，焦点可见，控件名称能说明作用和所属镜头，阶段变化和异步结果可由读屏确认。依据图 01、05、07 及浏览器可访问性树。 |

## 实施交接与验证

- 5.6 Luna 在获批后接手。主要落点为 [本机素材库](../../../dashboard/src/pages/LocalLibrary/index.tsx)、[本地视频向导](../../../dashboard/src/pages/LocalVideoWizard/index.tsx)、[视频组件页面](../../../dashboard/src/pages/VideoEnvironment/index.tsx) 和 [中](../../../dashboard/src/locales/zh.json)／[英文案](../../../dashboard/src/locales/en.json)。只有 E 获批时才涉及 [登录页](../../../dashboard/src/pages/Login/index.tsx)。复用当前的组件、路由和 API。
- 保留绿色版启动后立即可打开并登录、依赖按需安装、素材本机持有。把新手指引放在当前业务步骤内，沿用 [现有产品约束](../../PRD.md) 和 [工作台设计](../video-production-workbench/PRD.md)。
- 实施后从前端开发环境运行 `npx tsc -b`，并用上表用例做定向走查。用两个实机条件验证 C：首次缺组件，以及组件已就绪。查看真实 MP4 的保存和播放，再补键盘、读屏和窗口缩放的验证。按仓库规则将全套测试留给 CI。
